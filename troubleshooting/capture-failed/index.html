캡처와 파일 열기 문제

스크랩 결과가 기대와 다르면 먼저 저장이 진행 중인지, 일부 파일만 실패했는지, 저장한 파일을 여는 단계에서 문제가 생겼는지 구분합니다. 브라우저에서 캡처하는 확장 스크랩과 앱에서 URL로 만드는 스크랩은 접근하는 화면이 다를 수 있습니다. 원본 URL, 선택한 범위, 저장 포맷과 상태 문구를 함께 확인하면 필요한 조치를 좁힐 수 있습니다.

먼저 확인할 순서

섹션 제목: “먼저 확인할 순서”
  1. 목록과 진행 표시에서 해당 항목이 아직 수집 중인지 확인합니다. 페이지 로딩 중…, 캡처 중…, **저장 중…**은 서로 다른 단계입니다.
  2. 항목이 여러 개 진행 중이면 대기 중인 항목과 실행 중인 항목을 구분합니다. 잠깐 상태가 바뀌지 않았다는 이유만으로 같은 URL을 여러 번 저장하지 않습니다.
  3. 완료된 항목을 열고 원하는 미리보기 탭을 선택합니다. PNG나 JPG를 선택하지 않았다면 스크린샷 원본이 없을 수 있습니다.
  4. 폴더 열기로 실제 저장 파일을 확인합니다. 목록 제목과 썸네일만 보고 모든 형식이 정상 저장되었다고 판단하지 않습니다.
  5. 원본 페이지를 브라우저에서 직접 엽니다. 페이지 자체의 접속 실패, 로그인 요구, 이미지 미로딩 여부를 확인합니다.
  6. 로그인 후에만 보이는 화면이면 로그인한 브라우저의 확장으로 다시 스크랩합니다. 앱 URL 입력은 사용자의 브라우저 로그인 화면을 그대로 사용하지 않을 수 있습니다.
  7. 다시 저장한 항목에서 본문 끝부분과 이미지 몇 장을 확인합니다. 이전 항목을 지우기 전에 필요한 자료가 새 결과에 있는지 비교합니다.

상태와 원인 구분

섹션 제목: “상태와 원인 구분”
보이는 상태 먼저 확인할 것 조치
페이지 로딩 중… 원본 사이트의 응답과 인터넷 연결 원본을 직접 열고 로딩이 끝나는지 확인합니다.
캡처 중… 긴 페이지나 큰 이미지 처리 여부 캡처 완료를 기다리고 중복 요청을 줄입니다.
미디어 다운로드 중… 페이지 내 영상의 크기 이미지 저장 이후에도 미디어 처리가 이어질 수 있습니다.
스크랩 실패 항목에 표시된 오류 내용 원인에 맞춰 접근 방법을 바꿔 다시 시도합니다.
일부 형식만 있음 처음 선택한 저장 포맷 선택하지 않은 파일과 실패한 파일을 구분합니다.
파일을 찾을 수 없음 동기화와 실제 파일 위치 파일 다운로드를 마친 뒤 다시 엽니다.
본문을 열지 못했습니다 원본 본문 파일 읽기 가능 여부 편집을 시작하지 말고 다시 시도를 사용합니다.

빈 화면이나 로그인 화면이 저장된 경우

섹션 제목: “빈 화면이나 로그인 화면이 저장된 경우”

앱에 URL을 넣는 방식에서 로그인 안내가 저장되었다면 대상 사이트가 로그인 상태를 요구하는지 확인합니다. 브라우저에서 필요한 내용이 실제로 보이는 상태를 만든 뒤 확장 팝업으로 스크랩합니다. 확장은 사용자가 보는 탭을 캡처하므로 로그인 후 화면을 보존할 때 사용할 수 있습니다. 캡처 전에 팝업, 가림막, 쿠키 안내가 중요한 내용을 덮고 있지 않은지도 확인합니다.

이미지가 나중에 나타나는 페이지에서는 원본을 먼저 끝까지 살펴봅니다. 콘텐츠가 아직 로딩 중이라면 완성된 화면을 확인한 뒤 다시 저장합니다. HTML을 저장해도 로그인 서버와 연결되어야만 동작하는 기능까지 모두 오프라인으로 재현되는 것은 아닙니다. 읽어야 할 모습이 중요하면 이미지나 PDF 결과도 함께 확인합니다.

본문이 잘리거나 같은 무늬가 반복되는 경우

섹션 제목: “본문이 잘리거나 같은 무늬가 반복되는 경우”

확장의 전체, 콘텐츠, 사용자지정 중 어떤 범위를 선택했는지 확인합니다. 전체 글이 필요하지만 콘텐츠 감지가 짧은 영역만 찾았다면 전체로 비교합니다. 특정 영역만 필요하면 사용자지정으로 선택한 테두리를 확인합니다. 내장 프레임이나 별도 스크롤 영역이 있는 사이트는 눈에 보이는 바깥 페이지 높이와 실제 본문 높이가 다를 수 있습니다.

긴 페이지는 현재 버전에서 원본 배율을 유지하는 분할 캡처 방식으로 처리합니다. 이전 버전에서 큰 이미지의 반복이나 잘림이 생겼다면 앱 업데이트를 확인하고 새로 저장해 봅니다. 이미 저장된 잘못된 이미지가 앱 업데이트만으로 다시 캡처되지는 않습니다. 원본 페이지가 아직 열릴 때 새 결과와 비교합니다.

파일 없음과 본문 읽기 실패

섹션 제목: “파일 없음과 본문 읽기 실패”

다른 PC에서 만든 항목은 목록이 먼저 표시되고 실제 파일은 열 때 내려받을 수 있습니다. 동기화 배너가 다운로드나 계정 오류를 보여 주면 해당 상태부터 처리합니다. 다시 시도가 표시되면 다운로드 완료 뒤 누릅니다. 로컬 폴더에서 파일을 직접 옮겼거나 삭제했다면 원래 위치에 자료가 있는지 확인합니다.

본문을 열지 못했습니다 안내는 빈 문서가 새로 만들어졌다는 뜻이 아닙니다. 앱은 원본을 지키기 위해 편집을 막습니다. 읽기 오류가 있는 문서에 새 내용을 써서 덮어쓰려고 하지 않습니다. 동기화가 끝난 뒤 다시 열고, 계속 실패하면 해당 항목의 저장 폴더와 오류 문구를 함께 확인합니다. Markdown 미리보기 오류와 원본 웹사이트의 접속 오류도 구분합니다.

화면 캡처가 실패하는 경우

섹션 제목: “화면 캡처가 실패하는 경우”

새 화면캡처는 웹페이지 스크랩과 별도 기능입니다. macOS에서 화면 기록 권한이 없습니다가 보이면 안내된 시스템 설정에서 Aurora Scrap의 화면 기록 권한을 허용하고 앱을 다시 시작합니다. 권한을 바꾼 직후에는 이미 열려 있던 앱에 즉시 반영되지 않을 수 있습니다.

전체 화면을 독점하는 프로그램 때문에 자유 영역 선택을 열 수 없다는 안내가 나오면 해당 프로그램을 창 모드로 전환합니다. 또는 전체 화면 캡처를 사용합니다. 창 선택에 목록이 없으면 캡처하려는 창이 실제로 열려 있는지 확인합니다. 실패 문구에 따라 확인할 권한과 대상이 다릅니다.

재시도 전에 기록할 정보

원본 URL, 앱 버전, 앱 또는 확장 중 사용한 방법, 선택 범위, 저장 포맷, 오류 문구를 적어 둡니다. 같은 조건에서 반복되는지 확인하면 문제를 설명하기 쉽습니다.

자주 묻는 질문

섹션 제목: “자주 묻는 질문”

스크랩 완료인데 동영상이 없으면 실패인가요?

섹션 제목: “스크랩 완료인데 동영상이 없으면 실패인가요?”

페이지 저장과 동영상 다운로드 결과는 다를 수 있습니다. 영상 다운로드에 실패해 일반 스크랩으로 전환될 수도 있습니다. 저장된 스크린샷과 HTML을 확인하고 영상은 미디어 오류 안내에 따라 따로 점검합니다.

원본 파일이 있는데 앱에서만 열리지 않으면 어떻게 하나요?

섹션 제목: “원본 파일이 있는데 앱에서만 열리지 않으면 어떻게 하나요?”

파일 형식과 연결 프로그램을 확인합니다. 첨부를 열 수 없다는 오류는 파일 부재와 연결 프로그램 부재가 구분되어 표시됩니다. 파일이 실제로 존재하면 적절한 프로그램으로 열 수 있는지 확인합니다.

다시 시도하면 기존 스크랩이 고쳐지나요?

섹션 제목: “다시 시도하면 기존 스크랩이 고쳐지나요?”

파일을 여는 화면의 다시 시도는 해당 파일 읽기를 다시 진행합니다. 새 스크랩 실행은 새로운 저장 결과를 만드는 절차입니다. 어떤 화면에서 재시도하는지 확인하고 이전 자료를 먼저 삭제하지 않습니다.
